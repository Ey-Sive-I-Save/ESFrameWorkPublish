# User-Directed Action Authority

状态：现行项目授权合同。`UserDirectedLowRisk` 仅作为既有文件名和脚本名的兼容别名，不再表示低风险白名单。

## 授权规则

用户当前明确提出的目标、修改意图或动作，是项目内执行的授权来源。明确目标可以授权为实现该目标严格必要的多个文件，不要求用户预先知道内部路径。AICommand、TaskContract、AIBrain 计划、Skill 生命周期、路径风险等级和验证器结果均不得成为二次用户审批。

只有以下情况停止写入并向用户澄清：

1. 当前用户没有提出修改或动作；
2. 计划加入与目标没有必要关系的文件、功能、重构、清理、记录或副作用；
3. 目标或动作存在会显著改变结果的歧义；
4. 路径越出当前项目根；
5. 删除、重命名、Git 写、Unity/Runtime、交互式或常驻进程、对外产生副作用的进程、网络、发布或凭据访问没有被用户单独点名。

路径属于 `AGENTS.md`、`.agents/`、AIKnowledge、AIWarnings、AICommands、源码、`Assets/`、`ProjectSettings/`、`Packages/`、生成物或报告，只改变风险披露和验证强度，不改变用户授权。用户已经点名动作时，不再索取项目内部批准。

## 范围解释

- `direct`：用户点名的对象、结果或动作，以及实现它严格必要的项目内变更。
- `ambiguous`：存在两个会显著改变结果或副作用的合理解释；先澄清。
- `inferred-expansion`：顺便清理、无关重构、额外功能、自动写历程/审计、运行、发布、网络、删除或 Git 操作；默认拒绝。

AI 可以在开始时声明计划目标并直接实施。实施中新增目标时，必须重新判断它是否对当前目标严格必要；不是则取得新的当前用户指令。文件数量和字节阈值只触发复核提示，不撤销授权。

项目已有的本地静态验证器、Parser、编译器和格式化器，在它们对已授权目标严格必要、输入与超时有界、不联网、不安装依赖、不启动 Unity/Runtime 且不留下常驻服务时，属于质量验证而不是 `external-process` 专项动作。调用可执行文件本身不能成为扩大目标、访问外部系统或启动 Runtime 的理由。

## 编排与证据

直接项目修改不需要 AIBrain、AICommand 或 TaskContract。选用 AIBrain、Facade、Worker 或其他受管执行端点时，它们可以要求 PlanHash、合同和回执作为技术协议；这些字段不构成第二次用户许可，缺少时应尝试同一授权范围内的直接实现或报告通道能力缺失。

UTF-8、工作树保护、目标 diff、测试、SourceRef/ContentHash 和 Runtime/Release 证据仍是质量与声明门禁。它们可以使验证失败、条目 stale 或完成声明降级，但不能把用户明确请求改写为未授权。

## 验证器边界

`Test-ESUserDirectedLowRiskPolicy.ps1` 比较声明的用户范围与计划目标、规范化项目路径、操作类型和显式动作标记。`create`/`modify` 标签与当前文件存在性不一致时只输出复核信号，不撤销用户授权。仓库脚本无法独立读取或认证聊天内容，因此 `-ExplicitUserInstruction` 和 `-ExplicitAction` 必须由宿主根据当前用户消息提供；脚本只证明声明范围闭合，不能证明宿主诚实。

商业静态检查必须覆盖：普通修改、控制面修改、AIKnowledge 修改、缺少用户指令、计划范围扩张、项目越界、动作专项授权、凭据路径、绝对路径归一化，以及 create/modify 目标状态只产生非阻断复核。
