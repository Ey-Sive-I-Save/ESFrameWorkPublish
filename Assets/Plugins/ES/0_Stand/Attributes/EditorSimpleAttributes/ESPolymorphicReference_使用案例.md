# ES 多态引用自动编辑

`ESPolymorphicReference` 现在不需要业务字段添加额外特性。只要字段使用 Unity 原生的
`[SerializeReference]`，Odin 建立 `PropertyTree` 后，ES 编辑器 Drawer 就会自动接管该节点的
类型选择与对象编辑。

```csharp
[SerializeReference]
public Effect effect;

[SerializeReference]
public List<Effect> effects;
```

如果业务语义无法从字段本身推断，可以只补充轻量辅助特性：

```csharp
[ESFieldPolicy(ESFieldRequirement.Required)]
[ESFieldHint("为空时，触发流程不能继续。")]
[SerializeReference]
public Effect effect;
```

`Optional` 保持安静，`Recommended` 只显示建议状态，`Required` 才会把空值提升为阻断状态。

## 选择器如何接管

Drawer 只匹配 Odin 的 `SerializationBackend.UnityPolymorphic`，因此不会影响普通 class、
`UnityEngine.Object` 引用、Odin 自己序列化的多态值或普通集合。

选择器本身使用 `ESSearchDropdown`。切换类型、创建对象和清空对象都是明确点击后才发生；
替换已有类型或覆盖缺失类型时会二次确认，清空则是一键操作并接入 Undo。打开 Inspector、刷新、编译和展开对象不会自动
创建实例、清空引用、扫描资产或写入场景。

界面采用连续的“对象编辑条”布局：

- 左侧整块区域都可以展开/折叠，不要求精确点中小箭头；
- 顶部显示业务字段名，右侧是有完整命中区的“重选类型”入口（已选对象也保持可重选）；
- 第二行显示“目录 / 类型 · CLR 类型”的稳定语义；
- 已配置、未配置、类型缺失分别使用蓝色、灰色、橙色状态线；
- 元信息行由 `ESFieldRow` 追加轻量状态标记，不接管 Odin 的普通子字段控件；
- 嵌套 managed-reference 会显示“嵌套 N”层级标题和缩进内容，子节点仍可继续重选；
- 普通子字段继续使用 Odin 原生 Drawer，不再额外套多层卡片或重复标题。

`ESFieldRow` 目前只为 ES 状态字段追加轻量标记；普通 `float`、`int`、`bool` 等基础字段仍走
Odin 原生绘制路径，不会被强制包裹或改变控件行为。

## 类型目录来源

`ESTypeCatalog` 是 ES 对类型信息的统一缓存层。它不替换 Odin 的类型元数据，也不改变
Unity 的序列化格式，而是以字段声明的基类为根，通过 Unity
`TypeCache.GetTypesDerivedFrom(baseType)` 收集候选，再读取 Odin 的
`TypeRegistryItemAttribute` 生成 ES 目录项。

候选类型以字段声明的基类为根，通过 `ESTypeCatalog` 收集和缓存。
候选类型必须满足：

1. 具体、可序列化的 class；
2. 非抽象、非开放泛型、非 `UnityEngine.Object`；
3. 不属于 UnityEditor 命名空间；
4. 具有无参构造函数，且构造只在用户明确选择后执行。

业务目录优先读取项目已有的 Odin `TypeRegistryItemAttribute`：

```csharp
[Serializable]
[TypeRegistryItem("数值/固定伤害")]
public sealed class DamageEffect : Effect
{
    public float amount;
}
```

`/` 会直接生成选择器目录。没有 `TypeRegistryItem` 的类型不会被静默丢弃，而是进入“未登记类型”，
并显示 CLR 类型名与程序集信息。大型业务类型应沿用项目已有的 `TypeRegistryItem` 约定；不再
引入 `ESPolymorphicType` 这套重复元数据。

## 空值、集合和缺失类型

- 空值显示“选择类型创建”，不绑定打开界面或刷新自动创建。
- `List<T>` 或数组中的 managed-reference 元素沿用同一选择器；集合增删仍由 Odin 负责。
- 已保存但程序集/类型无法解析时，显示错误原因和原始类型名，不自动清空。
- 只有用户明确选择替代类型并确认后，才覆盖缺失引用。
- 清空已有对象是一键快速操作，保留 Unity/Odin 的 Undo 能力，可立即使用 `Ctrl+Z` 恢复。

## 状态语义

ES 的状态颜色不把“空值”和“错误”混为一谈：

- `Empty`：尚未选择类型，保持中性，不代表配置损坏；
- `Ready`：当前类型可正常编辑，使用嵌套深度色阶；
- `Error`：原类型缺失或无法解析，显示原因并提示替代路径；
- `Warning` / `Modified` / `ReadOnly`：由后续诊断、事务和字段行组件复用同一套状态色。

因此可留空的多态字段不会在打开 Inspector 时制造错误噪音，只有真正无法继续的状态才会提高视觉等级。

## 多目标编辑

ES 允许同时编辑 2～10 个对象。若 ES 发现它们当前的多态类型或空值状态不同，选择器不再假装显示
“第一个对象”的类型，而会显示“多目标不一致”，并说明重新选择类型会覆盖全部已选对象。批量替换时，
ES 会为每个目标分别创建独立的 managed-reference 实例，避免多个宿主意外共享同一个引用对象。
在不一致状态下，ES 也不会继续绘制第一个对象的子字段；先统一类型后再编辑子字段，避免把代表值误当成所有对象的共同值。

超过 10 个对象时，字段保持可查看但进入只读保护；请减少选中对象后再进行类型替换或清除。

## 性能边界

类型目录按声明基类缓存：

- 第一次请求某个基类的目录时才查询 `TypeCache` 并建立目录；
- 普通 Inspector 重绘只读取缓存，不枚举程序集、不扫描资产、不扫描场景；
- 选择器真正打开时才创建菜单项；
- 编译完成或程序集重载时清空 `ESTypeCatalog` 缓存，避免关闭 Domain Reload 后残留旧类型。

## 绘制方案切换

绘制方案目前通过 Unity 菜单切换：

```text
【ES】/自动化与开发/编辑器扩展/多态引用/绘制方案/【ES】自定义渲染
【ES】/自动化与开发/编辑器扩展/多态引用/绘制方案/Odin 默认动态渲染
```

集合元素绘制独立控制，不会跟随单体 `SerializeReference` 开关强制绑定：

```text
【ES】/自动化与开发/编辑器扩展/多态引用/项目默认集合绘制/【ES】标准集合卡片
【ES】/自动化与开发/编辑器扩展/多态引用/项目默认集合绘制/Odin 默认集合元素绘制
```

类型选择器顶部的“集合”按钮也可以直接切换。关闭后，集合中的多态元素回到 Odin 默认绘制；
单体引用仍可继续使用 ES 绘制。集合的增删、排序和容量控制仍由 Odin 负责，开关只控制集合元素
内部的多态内容绘制。

方案保存在当前 Unity 项目的 `EditorPrefs` 中，不写入场景、Prefab 或资产。类型选择器的
候选数据由 `ESTypeCatalog` 提供，ES 保留自己的搜索和目录描述；不会依赖 Unity 内部私有
`AdvancedDropdownGUI` 构造函数或方法注入。

## 案例

挂载 `ESPolymorphicReferenceCase` 到任意 GameObject：

- “触发效果”验证单个 `[SerializeReference]`；
- “单体引用”“嵌套引用”“效果序列”验证 `ESEditorSection` 与多态 Drawer 的组合；
- “效果序列”验证多态集合元素和 `CompositeEffect` 的二层嵌套；
- “未登记类型验证”验证没有 `TypeRegistryItem` 的候选类型；
- `DamageEffect`、`HealEffect`、`PlayAudioEffect` 和 `CompositeEffect` 验证业务目录树。

建议按以下顺序验收：

1. 在“触发效果”中重选类型，确认弹窗显示当前类型和目标类型；
2. 修改子字段后按 `Ctrl+Z`，确认类型和字段值一起恢复；
3. 点击右侧 `×` 快速清除，再按 `Ctrl+Z` 恢复；
4. 展开“二层嵌套”或“效果序列”中的“复合效果”，确认出现“嵌套 1”及其子节点，并继续操作“主效果”和“备用效果”；
5. 在“未登记类型验证”中打开目录，确认“未登记类型”分组可见。

若要验证缺失类型诊断，请先在测试场景中保存一个具体类型，再临时移动/重命名该类型的
程序集或完整类型名，重新编译后观察错误提示；不要在正式资产上做此实验。

## 边界回归案例

挂载 `ESPresentationBoundaryCase` 后，可用同一个脚本验证批量和深层数据：

1. 复制 2～10 个实例并同时选中，修改“共享节点”，确认所有实例一起变化；
2. 复制到 11 个实例，确认多态选择器进入只读状态，并提示“批量编辑上限 10 个对象”；
3. 在“节点数组”和“节点列表”中验证空槽、不同类型和集合元素独立重选；
4. 展开“8 层嵌套根节点”，确认缩进、边框和选择器不会错位或相互覆盖；
5. 对上述操作使用 `Ctrl+Z`，确认批量写入和嵌套写入都能整体撤销。

也可以直接使用菜单：

- `【ES】/验证与诊断/测试与验收/编辑器扩展/ES 编辑器扩展/创建多态边界测试层级`
- `【ES】/验证与诊断/测试与验收/编辑器扩展/ES 编辑器扩展/选择 2 个不一致对象`
- `【ES】/验证与诊断/测试与验收/编辑器扩展/ES 编辑器扩展/选择 10 个多目标对象`
- `【ES】/验证与诊断/测试与验收/编辑器扩展/ES 编辑器扩展/选择全部多目标对象（11 个）`

也可以在 `【ES】/常用窗口/工具启动器` 中搜索“ES 多态边界测试”执行正式的“测试与验收”菜单入口；
测试层级本身不注册到“常用窗口”。

创建后会生成一个根对象和 12 个互相独立的子对象：1 个基准案例、11 个多目标案例。
前 10 个多目标案例使用相同的“共享节点”类型；第 11 个使用不同类型，并让“混合节点”为空。
这样可以直接在 Hierarchy 中进行多选，不需要手动复制和改名：选择 10 个时验证正常批量态，选择 2 个
不一致对象时验证类型/空值混合提示，选择全部 11 个时验证 10 个对象上限保护。

超过上限后，ES 不会遍历全部对象推导“是否不一致”，避免 Inspector 重绘随选中数量线性增长；它只显示明确的
只读原因。若要观察“不一致”警告，请使用“选择 2 个不一致对象”。
