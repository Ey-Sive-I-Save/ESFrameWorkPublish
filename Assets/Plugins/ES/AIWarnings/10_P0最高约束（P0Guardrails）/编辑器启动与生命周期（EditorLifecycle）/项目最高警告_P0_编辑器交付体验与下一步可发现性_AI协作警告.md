# 项目最高警告 P0：编辑器交付体验与下一步可发现性

职责：所有 ES 编辑器工具、自动化入口、AI 产物和生成文件都必须围绕用户的真实工作目标设计，降低配置、使用、查询、交付和恢复阶段的学习成本、定位成本与误操作成本。

## 最高结论

编辑器功能的完成标准不只是源码存在、窗口能打开或文件生成成功。完整标准覆盖五个阶段：配置、使用、查询、交付、恢复。每个阶段都必须提供可理解的状态、就近的操作入口和明确的下一步；用户不应为了完成一个目标被迫按工具作者预设的线性顺序反复跳转。

“快速打开”不是孤立的 P0 功能；它是编辑器低摩擦交付和用户下一步可发现性标准中的强制项目。

## 五阶段交互要求

### 配置

- 默认值必须安全且可解释；高风险选项必须说明影响范围、权限和回滚方式；
- 配置入口应靠近实际使用入口，并支持从结果或错误状态反向定位配置；
- 不得把必要配置隐藏在用户无法发现的 EditorPrefs、脚本参数或临时文件中；
- 配置缺失时应说明最小补全动作，不得只抛出空引用或泛化错误。

### 使用

- 用户应能从目标、名称、搜索或结果入口进入功能，而不是只能记住固定菜单路径；
- 常用动作提供快捷入口，危险动作提供确认、预览或 dry-run；
- 操作应允许合理的跳步、返回、重试和取消，不得强迫用户完成与当前目标无关的中间步骤；
- 空状态、等待状态和失败状态都要说明当前状态与可行下一步。

### 查询

- 查询、筛选、定位和历史结果应支持稳定 ID、名称、路径或任务 ID；
- 结果应区分主结果、日志、证据、临时文件和失败详情；
- 查询不到结果时要说明搜索范围、排除条件和下一种可行查询方式；
- 不得要求用户在大量 Console、目录或 JSON 中人工猜测目标对象。

### 交付

- 面向用户继续处理的主产物必须提供直接入口：快速打开、项目窗口定位、打开报告、复制路径或继续处理；
- CI、无 UI、临时文件和安全敏感产物可使用稳定路径、机器可读索引或受控访问方式替代按钮；
- 只在 Console、聊天文本或日志中打印路径，不算完整交付；
- 失败、部分成功和待输入状态必须保留可恢复的下一步。

### 恢复

- 窗口重开、域重载、编辑器重启或任务中断后，用户应能恢复到最近明确状态；
- 恢复入口必须显示状态是否过期、依赖是否漂移以及最小修复动作；
- 不得要求用户凭记忆重新拼接路径、参数和操作顺序。

### 信息密度与排版可读性

- 首屏优先展示当前状态、用户目标、关键结果和下一步动作；实现细节、原始日志和完整 JSON 默认折叠或延迟展开；
- 信息必须按“标题/状态 → 关键结论 → 操作入口 → 证据与详情”的层级排列，不得把所有字段平铺成无差别文本墙；
- 长路径、哈希、SessionId、异常堆栈和大段 JSON 必须支持复制，并提供截断显示、悬停完整值或详情展开；
- 表格、列表和卡片的列名、单位、状态含义和排序依据必须明确；不能只靠颜色表达成功、失败、警告或阻断；
- 中文用户界面优先使用清晰、稳定、可扫描的中文标签；技术名词可保留原文，但必须有中文语义说明；
- 相关信息应就近分组，操作按钮与其影响对象相邻；避免用户在多个面板之间来回寻找关联信息；
- 空状态、加载中、部分成功、失败、权限不足和不可用状态必须使用不同且可理解的版式，不得只显示空白区域或红色日志；
- 排版必须保留足够留白、对齐和视觉分组，不能用堆叠按钮、过密文本或过长单行内容降低扫描效率；
- 窗口尺寸变化、窄屏和高 DPI 下仍必须保持关键信息与主要动作可见；
- 信息密度应服务于决策效率：高级详情可以丰富，但不能挤占用户完成当前目标所需的主路径。

## 适用范围

- 主要约束用户可见的 `EditorWindow`、Inspector、弹窗、向导、诊断面板、结果面板和工具栏入口；
- Unity EditorWindow、Inspector、Drawer、菜单工具和预览工具；
- AI、C#、Python、PowerShell 或 Worker 生成的报告、配置、日志、快照和结果文件；
- 自动化任务、编译结果、场景扫描结果、审计状态和交接产物；
- 任何需要用户从当前结果继续定位或处理的编辑器交付。

纯内部日志、机器间协议、序列化数据结构和不直接面向用户的后台缓存不直接套用视觉排版要求，但其对外展示层仍必须遵守本规则。

## 强制交付要求

1. 面向用户继续处理的主结果，展示附近必须提供至少一个明确的下一步入口：`快速打开`、`在项目窗口定位`、`打开报告`、`复制路径`、`继续处理`或等价动作。
2. 所有生成文件必须返回稳定的绝对路径或项目相对路径；有 UI 的宿主应同时提供可点击/可执行的打开或定位动作，无 UI/CI/安全敏感场景则提供机器可读索引、受控访问方式或最短手工动作。
3. 路径、文件名、任务 ID、报告 ID 和窗口标题必须能互相对应，避免用户看到结果却无法判断哪个文件属于本次操作。
4. 打开动作必须经过路径策略校验，只允许打开本次任务声明的输出根或明确的项目内安全路径；禁止借“快速打开”绕过权限边界。
5. 生成失败、部分成功或等待输入时，也必须显示当前状态和下一步动作；不能只显示异常文本。
6. 不得要求用户重复执行 AI 已经知道的路径查找、文件筛选或窗口导航步骤。

## 交互判断顺序

新增或修改编辑器功能时，先回答：

1. 用户当前真正要完成的目标是什么？
2. 当前阶段是配置、使用、查询、交付还是恢复？
3. 用户完成当前动作后最可能做什么？
4. 是否已经提供就近且可理解的入口？
5. 是否允许合理跳步、返回、取消和重试？
6. 如果产物写入磁盘，用户能否打开、定位、复制路径或通过宿主等价方式访问？
7. 如果存在多个产物，用户能否区分主结果、日志、证据和临时文件？
8. 失败时用户能否从当前界面恢复，而不是重新寻找入口？

## 禁止事项

- 禁止对面向用户继续处理的主结果只输出“已生成：某路径”而没有打开/定位/复制动作；
- 禁止把临时目录、缓存目录或不稳定的时间戳路径当作用户唯一入口；
- 禁止用自动弹窗、全局抢焦点或无授权打开外部程序代替可发现的用户操作；
- 禁止快速打开动作访问未声明的任意路径、凭据、系统目录或外部网络资源；
- 禁止把交付、查询或配置体验问题降级为“用户自己熟悉路径即可”；
- 禁止为了形式上的流程完整，强迫用户执行与目标无关的中间步骤；
- 禁止把作者熟悉的内部目录、类型名或实现顺序当成用户必须学习的使用流程。

## 验收门禁

- 配置、使用、查询、交付和恢复五个阶段均有明确状态和下一步动作；
- 首屏、详情展开、长文本、状态表达和窄屏布局均通过可读性检查；
- 首屏在不滚动时能看到当前状态、核心结论和主操作；
- 关键操作无需横向滚动即可完成；
- 长路径、哈希、SessionId 和异常详情可以复制完整值；
- 失败状态至少包含原因、影响范围和恢复动作；
- 窄窗口、高 DPI 和常用缩放比例下，主路径截图检查通过；
- 视觉验收记录窗口尺寸、缩放比例、状态场景和截图证据；
- 常用目标支持快速定位，合理跳步、返回、取消和重试；
- 成功、失败、部分成功和待输入状态均有明确下一步动作；
- 生成的主产物、报告和证据均有快速打开或项目内定位入口；
- 打开/定位入口经过路径策略和权限校验；
- 不依赖用户手工在项目树或文件系统中搜索；
- 入口在域重载、窗口重开和重复执行后仍能正确指向当前结果；
- 文档交付、AI 交付和 Unity 实机交付都分别记录入口证据。
