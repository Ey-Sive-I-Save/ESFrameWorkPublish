# P0：保留通用泛型底座，长期合同使用领域具体类型

> 状态：现行 P0 约束。  
> 适用范围：ES 自定义泛型容器进入 Unity/Odin 持久化数据、GameCore/RuntimeData 权威表、稳定跨模块 API 或其他长期核心合同时。  
> 不适用范围：普通 BCL 集合、局部算法、测试临时对象，以及不承担领域身份的短生命周期实现型泛型。

## 最高结论

本规则约束的是**通用泛型底座进入长期业务合同的方式**，不是禁止泛型。

1. `ESEnumStringMirrorMap<TEnum, TValue>` 等通用泛型底座必须保留、复用和独立测试；不得因本规则被删除、禁用、弃用或复制进业务文件。
2. Unity/Odin/Prefab/Scene/ScriptableObject/存档长期字段，以及成熟跨模块权威合同，应由具有真实领域职责的 `sealed` 具体类型承载。
3. `sealed` 具体类型只固定领域身份和演进边界，不自动证明序列化兼容、资产迁移、IL2CPP、Unity 或发布验收已经完成。
4. 是否要求迁移，取决于数据是否已经承担兼容承诺，而不取决于“磁盘上是否存在旧数据”。正式发布内容、玩家存档、UGC、外部版本协议、不可丢失的生产数据和用户明确要求保留的数据，改变结构前必须建立显式、可恢复、可审计的迁移闭环。
5. ESFramework 处于框架开发阶段时，旧 Prefab、Scene、ScriptableObject、测试资产、示例资产和开发存档默认属于可丢弃开发数据；允许直接进行破坏性版本切换，不要求保留旧载荷接收能力、编写迁移器或逐次取得用户授权。
6. 开发阶段的数据丢失许可只撤销旧格式兼容责任，不证明新格式正确。新权威路径仍必须唯一，并按当前任务取得序列化往返、运行消费和对应层级的验证证据。

删除、迁移或废止通用底座属于独立架构变更，必须取得当前明确授权和完整影响评估。本规则本身永远不构成删除授权。

## 判定范围

### 命中本规则

ES 自定义泛型的闭合类型满足下列任一条件，即进入长期合同候选：

- 由 `[SerializeField]`、`[SerializeReference]`、`[OdinSerialize]` 或等价机制持久化；
- 保存于 Prefab、Scene、ScriptableObject、存档、网络快照或长期配置中；
- 成为 GameCore、RuntimeData、全局索引或跨模块公共 API 的权威字段；
- 需要独立版本迁移、领域校验、稳定错误码、作者工具或发布门禁；
- 修改底座布局、泛型参数或公共写 API 会直接影响既有资产或多个稳定消费者；
- 需要固定 IL2CPP/AOT 可见的领域闭合边界。

命中候选后仍须证明具体类型承担真实职责；不得仅凭文本扫描结果机械包装。

### 默认不命中

- 方法局部变量、内部算法和测试临时对象；
- 普通非序列化私有缓存；
- 短生命周期 Pool、Lease、Handle、Scheduler、Builder 等实现结构；
- 泛型底座自身及其独立测试；
- `List<T>`、`Dictionary<TKey, TValue>` 等普通 BCL 容器，除非另有领域 P0 明确约束；
- 未成为权威状态或稳定公共合同的普通闭合泛型使用。

## 领域具体类型要求

长期合同字段不得直接声明 ES 自定义闭合泛型，更不得把相同闭合形式散布到多个资产或系统。应先建立唯一、可搜索的领域类型，再由长期持有者声明该具体类型。

```csharp
// 不符合：长期序列化字段直接暴露通用闭合泛型。
[SerializeField]
private ESEnumStringMirrorMap<DefaultTransformKey, Transform> transformMappings;

// 符合：领域类型固定参数、身份、迁移和挂点语义。
[Serializable]
public sealed class EntityTransformMap
    : ESEnumStringMirrorMap<DefaultTransformKey, Transform>
{
    // Entity 挂点领域 API、不变量或诊断。
}

[SerializeField]
private EntityTransformMap transformMappings;
```

具体类型可以使用 `public sealed` 继承。仅因为“不希望普通用户调用”某个继承得到的方法，不得改成组合、程序集内部实现或额外只读 View；ES 自有非普通用户真实入口应使用 `Internal_` 前缀。只有序列化布局、独立不变量、生命周期所有权、安全或程序集依赖等真实边界成立时，才按对应职责选择组合或接口。

具体类型必须至少承担一项可验证职责：

- 固定本领域唯一的泛型参数组合和类型身份，且该身份实际承担 Unity/Odin 序列化类型、IL2CPP/AOT、版本迁移目标或稳定公共合同边界；
- 维护领域不变量、冲突策略或写入权限；
- 承担序列化版本、旧数据迁移或反序列化修复；
- 隔离作者态写入与运行时只读接口；
- 提供领域 API、稳定诊断、Inspector、批量校验或发布门禁；
- 固定 IL2CPP/AOT 与裁剪保留边界。

单纯固定泛型参数、改名或声明空 `sealed` 子类不构成真实职责。只有当该类型身份本身已经成为可验证的序列化、AOT、迁移或稳定公共合同边界时，固定参数和身份才可单独成立。其他空壳包装不合格；此时应先补足领域职责，或证明该字段实际上不属于长期合同并保留直接泛型使用。

## 继承与组合

| 领域需要 | 推荐方式 |
|---|---|
| 类型身份已实际承担序列化、AOT、迁移或稳定公共合同边界，并允许沿用底座公共 API | `sealed` 具体继承 |
| 只是不希望普通用户调用 `Clear`、`Remove`、任意写入等能力 | 保留真实结构；ES 自有非普通用户入口直接使用 `Internal_` 前缀，不得以此为由增加组合或只读 View |
| 公共发布合同确实只读，写入泄漏会破坏不变量、数据完整性或安全边界 | 按真实合同使用组合或只读接口，并证明其独立职责；不得仅凭“用户不该用”成立 |
| 需要独立序列化布局、版本或跨后端迁移 | 优先组合包装 |
| 底座没有正式继承契约 | 不得擅自解除 `sealed`；使用组合或先设计继承契约 |

`sealed` 继承和 `new` 成员隐藏都不会自动收窄基类公共 API。ES 标准不为普通使用引导伪造访问控制：非普通用户入口使用 `Internal_` 明示边界。只有真正需要编译期、程序集级或安全隔离时，才允许通过组合或接口改变结构，并必须说明结构本身承担的职责。

## 序列化与迁移硬门禁

`sealed` 具体类型不等于序列化安全。它不能单独证明：

- Unity 能保存并重载泛型基类中的字段；
- 字段重命名、容器改形或 Odin/Unity 后端切换可以自动迁移；
- Prefab、Scene、SO 或存档中的旧数据不会静默丢失；
- IL2CPP、裁剪和 Player 构建保留了所需具体类型；
- 编辑器编译、Test Runner、PlayMode 或发布验收已经通过。

先判断目标数据是否已经承担兼容承诺。只有正式发布内容、玩家存档、UGC、外部版本协议、不可丢失的生产数据，或用户明确要求保留的数据发生结构变化时，交付前必须完成：

1. 识别全部受影响资产、场景、SO、存档版本和公共 API；
2. 保留能接收旧载荷的桥接字段或专用旧版本读取器；
3. 在任何写入前完成全量预检，并对空引用、重复键、别名冲突和新旧数据不一致硬阻断；
4. 采用显式用户动作或受管批处理执行迁移，禁止在 Drawer、`OnGUI`、`OnValidate`、`InitializeOnLoad` 或普通运行时路径静默迁移；
5. 在项目内创建可校验备份，记录目标路径、字节数和内容哈希；
6. 保存后卸载并重新加载真实资产，逐项比较稳定 Key、值、对象引用或可证明等价的路径快照；
7. 任一步失败时停止后续写入，恢复所有已修改目标，并逐文件校验恢复后内容与迁移前记录的 SHA-256；任何目标恢复或哈希校验失败均为硬阻断，必须明确报告“恢复不完整”，不得宣称回滚成功；
8. 迁移、重载和相关测试全部通过后，才可在后续独立变更中移除旧载荷接收能力。

`FormerlySerializedAs` 只适用于 Unity 能表达的兼容字段重命名，不得用于证明字典拆并、容器换型、泛型布局变化或 Odin 到 Unity 的结构迁移已经安全。

### 框架开发阶段的数据重置政策

ESFramework 当前采用开发期快速演进政策：在用户明确宣布进入兼容维护、正式内容生产或发布阶段前，框架自身的旧序列化数据默认允许丢失。执行破坏性版本切换时：

1. 不要求为每次字段换型、容器改形或序列化后端切换单独请求用户授权；
2. 不要求保留旧接收字段、兼容读取器、迁移器、旧格式双读双写、逐资产等价迁移或迁移回滚链；
3. 在当前任务已经授权的实现范围内，应移除失效的旧权威、隐式回退和半启用兼容路径，只保留一个新权威来源；
4. 应在交付说明中直接列出会被重置的旧数据类别和需要重新作者化或重新生成的内容，但无需为每次开发期重置更新长期状态或建立迁移档案；
5. 必须验证新格式自身能够保存、卸载、重载并被真实消费者读取；未取得的 Unity、PlayMode、Player 或 IL2CPP 证据继续标为缺口；
6. 对外结论使用“开发期破坏性版本切换，旧载荷不兼容且允许丢失”，不得写成“迁移完成”或“向后兼容”。

框架总体仍处于开发阶段，不能自动把已经发布给用户、进入正式内容生产、承载玩家/UGC 数据或形成外部兼容承诺的数据降级为可丢弃数据。此类数据仍执行上一节完整迁移门禁。AI 不得因为一次开发期硬切反复报告“与迁移 P0 冲突”；只有发现目标实际属于兼容承诺范围时，才报告迁移阻断。

本政策只免除框架开发数据的旧格式迁移责任，不授权 AI 自行发起源码、资产、场景或配置改造，也不授权删除、Git、发布或扩大当前任务范围。实施破坏性变更仍必须由当前用户请求或既有任务授权覆盖；已经获得实现授权后，不再为“旧数据是否可以丢失”重复请示。

## 验证证据分层

以下证据不得互相冒充：

| 证据 | 只能证明 |
|---|---|
| 源码检查 | 类型关系、字段声明、算法唯一性和迁移入口存在 |
| 生成 `.csproj` 构建 | 当前生成清单收录的源码可静态编译 |
| 手动调用 `OnAfterDeserialize()` | 回调算法在内存对象上工作 |
| Unity Serializer 往返测试 | Unity 实际保存、导入、卸载和重载后数据保持 |
| 真实资产迁移验证 | 指定存量资产的新旧数据等价且旧载荷已清除 |
| Test Runner / PlayMode / Player / IL2CPP | 对应层级的运行或构建行为 |

临时 MSBuild 注入、手改 `.csproj` 或仅比较源码时间只能作为开发期诊断，不能作为 Unity 已导入、资产已迁移或发布可用的证据。

## 自动化与 AI 禁令

- 禁止把“长期合同使用具体类型”解释成“项目禁止泛型”；
- 禁止依据本规则删除、禁用或停止维护通用泛型底座；
- 禁止把通用算法复制进 Entity、Story、Localization 等领域文件；
- 禁止扫描到闭合泛型字段后自动删除、替换或批量生成包装类型；
- 禁止为了扫描归零给每个泛型、BCL 集合、Pool、Lease 或局部变量创建业务空壳；
- 禁止在兼容承诺范围内没有迁移器和真实资产往返验证时改变长期序列化字段；框架开发阶段的可丢弃数据按本规则允许直接硬切；
- 禁止把本规则已经允许的开发期数据重置再次报告为 P0 冲突，或要求用户为每次重置重复授权；
- 禁止把底层静态编译、内存回调测试或启动上下文验收描述成 Unity/资产/发布验收；
- 禁止在当前无明确授权时写 Git、历史、审计状态、发布状态或删除旧资产。

## 审查流程

发现候选字段后，按顺序回答：

1. 它是否命中长期序列化或成熟核心合同？
2. 目标数据属于框架开发阶段可丢弃数据，还是已经承担正式发布、玩家/UGC、生产内容、外部协议或用户保留承诺？
3. 具体类型能固定什么领域身份、不变量、权限、迁移或诊断？
4. 是否仅因为不希望普通用户调用继承 API 而准备改成组合或只读 View？若是，应保留结构并对 ES 自有真实入口使用 `Internal_` 前缀；若必须真正隔离，依据是什么？
5. 是否已有 Prefab、Scene、SO、存档或公共 API 依赖当前结构？这些依赖是否处于兼容承诺范围？
6. 若属于兼容承诺范围，迁移能否做到预检、备份、受控写入、失败时全目标恢复和保存后重载等价验证？
7. 当前证据属于源码、静态编译、Unity 往返、真实资产迁移还是运行/发布验收？

第 1 项不成立时，本规则不要求包装。第 1 项成立但第 3 项无法证明时，禁止制造空壳交差，应先完成领域设计。第 2 项确认属于框架开发阶段可丢弃数据时，可以直接硬切，不要求回答第 6 项，也不得报告迁移 P0 冲突；属于兼容承诺范围且第 6 项未闭环时，禁止修改存量长期序列化形态。

## 状态记录边界

本 P0 只保存长期规则，不保存日期性扫描快照、当前命中数量、具体模块完成度或一次构建结果。

- 当前实现和验收状态写入 `00_开始阅读（Start）/当前状态（CurrentStatus）.md`；
- 一次性扫描候选、日期、范围和证据写入明确的审计报告；
- 模块成熟度由模块状态治理入口记录；
- 任何状态记录都不能反向修改或弱化本 P0。
