# 项目最高警告 P0：AI 交付声明与责任契约

状态：现行强约束。

适用范围：所有由 AI 设计、修改、生成、验证或交付的 ESFramework 源码、编辑器工具、资源、场景、运行时功能、自动化结果和技术结论。

## 最高结论

AI 不得把“源码存在”“按钮存在”“静态编译通过”或“临时预览成功”描述成用户目标已经完成。完成声明必须与实际证据等级绑定，并主动列出未验证项、阻断原因、影响范围和下一步动作。

如果证据不足，必须降低结论等级；不得用相邻证据替换缺失证据。用户没有义务通过追问来发现 AI 未尽到的责任。

## 一、交付证据等级

| 等级 | 允许声明 | 不允许越级声明 |
|---|---|---|
| S0 设计 | 已完成方案、约束和实现计划 | 已实现、可用、已验收 |
| S1 源码 | 目标源码已修改，路径和入口存在 | 编译通过、Unity 可用、运行时可用 |
| S2 静态编译 | 指定 `.csproj` 或静态检查通过 | Unity Editor 编译、域重载、运行时行为 |
| S3 Unity 导入 | Unity Editor 导入/域重载/Console 通过 | 真实交互、PlayMode、发布可用 |
| S4 编辑器交互 | 指定窗口和操作在 Unity Editor 中真实完成 | PlayMode、Player、性能、发布通过 |
| S5 运行时 | EditMode/PlayMode/运行观察通过 | Player、IL2CPP、发布完成 |
| S6 发布 | Player/IL2CPP、资源、性能和发布链路按范围通过 | 超出测试范围的商业级或全平台结论 |

报告必须写明当前最高等级，例如：`当前等级：S2（静态编译通过，Unity 实机未验收）`。

## 二、强制交付报告字段

任何“完成”“可用”“已支持”“已修复”类结论，必须同时回答：

```text
目标：用户要完成的真实结果
实际修改：修改了哪些文件、资产、场景或运行链路
当前等级：S0-S6
已验证：逐项列出命令、Unity 操作、测试、场景或运行证据
未验证：尚未执行或无法证明的部分
阻断原因：缺失工具、环境、权限、输入、外部依赖或真实失败
影响范围：未验证项对用户结论的影响
下一步：最小可执行的补验或修复动作
```

未验证项为空时必须明确写 `无`；不能省略字段。

### 性能与分配任务附加合同

任务涉及排序、筛选、批处理、缓存、容器复用、性能对比或任何低 GC / 0 GC 声明时，实现在开始前、交付在结束前都必须回答：

```text
结果身份：返回原对象、新对象、稳定 View，还是写入调用方缓冲
修改语义：是否原地修改输入，是否保持重复项和稳定顺序
工作区所有权：实例、调用方、线程、任务或对象池
分配阶段：首次调用、预热后稳态、容量突破、异常路径
并发边界：是否允许并发、重入、跨线程或异步延续
验证证据：源码检查、分配计数、Profiler、Player 或目标平台
```

只完成编译或只在源码中未发现显式 `new`，不得省略上述字段，也不得宣称实际 0 GC。业务结果类型和对象身份必须符合用户目标；内部位权重、索引、临时列表或快照不得擅自成为公共交付结果。

## 三、证据替换禁止

以下等价关系一律禁止：

- `ESWorldMapAsset` 保存成功 ≠ `TerrainData.asset` 保存成功；
- `PreviewScene` 显示正确 ≠ 正式 Scene、Prefab 或运行时地形正确；
- `Heightfield` 修改成功 ≠ Unity Terrain 后端已同步；
- `.csproj` 编译通过 ≠ Unity Editor 编译或 ReloadDomain 通过；
- 按钮可见 ≠ 用户操作闭环完成；
- 代码路径存在 ≠ 运行时、碰撞、导航、资源收集或发布可用；
- 单元测试通过 ≠ 真实 Unity 交互、PlayMode、Profiler 或 Player 通过。

编辑器临时对象、缓存、截图、日志和模拟数据只能作为对应范围的证据，不能代表正式资产或发布产物。

## 四、未尽责任的主动披露

当用户目标未完全达成时，AI 必须主动写出：

```text
我尚未完成的责任：
未完成原因：
对用户的实际影响：
完成所需条件：
```

禁止使用“基本完成”“应该可以”“理论上支持”“看起来没问题”等模糊措辞代替证据。若任务被外部条件阻断，必须报告 `Blocked`，并说明已经尝试的安全替代路径；不得静默切换到另一个未授权数据源或验证来源。

## 五、交付结论状态（不替代模块成熟度）

源码和报告中的交付结论使用：

- `Designed`：只有设计；
- `Implemented-Unverified`：源码已实现，但关键实机或运行证据缺失；
- `Blocked`：因外部条件无法继续；
- `Failed`：已执行验证但结果失败；
- `Accepted`：满足本任务明确的验收范围；
- `Released`：满足发布范围和发布证据。

`Implemented-Unverified`、`Blocked`、`Failed` 不得在标题、摘要、聊天结论或 UI 状态中被压缩成“完成”。

模块成熟度只使用 `Proposed -> Scaffolded -> Experimental/Implementing -> Integrating -> Verifying -> Stable -> Deprecated -> Archived`；S0-S6 只描述当前证据等级。三者必须并列写出，禁止把 `Implemented-Unverified` 或 `Accepted` 称为模块成熟度。

### AIWarnings 证据写入边界

AIWarnings 不是编译日志或 Warning 台账。现行规则和活跃状态只记录证据等级、适用范围、验证时间、Git 基线和可重读证据入口；不记录编译失败列表、Console 文本、错误码或 Warning 数量。

构建失败仍必须在当次交付中主动披露阻断原因和可复读日志入口，但不得把瞬时诊断明细复制进 `当前状态（CurrentStatus）.md`。历史复盘只有在失败机制本身是长期规则时才保留最小必要事实。

## 六、地图与正式资产专项门禁

涉及地图、地形、场景或资源输出时，至少区分以下权威对象：

1. ES 作者态资产（例如 `ESWorldMapAsset`）；
2. ES Heightfield 或其他数据源；
3. Unity `TerrainData` 正式资产；
4. 正式 Unity Scene / Prefab；
5. 运行时加载、碰撞、导航和发布产物。

只有实际写入并重新读取目标对象，才能声明该对象已保存。只完成 1、2 不得声明 3、4、5 已完成；只完成 3、4 也不得自动声明运行时和发布已通过。

## 七、责任判断

AI 的交付责任不是“尽可能修改源码”，而是：

`识别真实目标 -> 修改正确权威对象 -> 执行匹配等级的验证 -> 披露证据缺口 -> 给出可恢复下一步`。

如果 AI 误报完成、隐藏未验证项、用低等级证据替代高等级证据，视为交付声明不合格；后续修复报告必须明确指出原结论被哪一条契约纠正。
