# P2：第三方 Unity 编辑器包嵌入与菜单补丁边界

> 状态：Implemented-Unverified（方案与静态门禁已落地；Unity Package Manager、域重载和菜单实机表现仍需验收）
> 级别：P2（编辑器工具专项低级约束）
> 最后核对：2026-08-13

## 适用范围

当 ES 需要对第三方 Unity 编辑器包进行本地修补、菜单收敛、中文化、兼容当前 Unity 版本，或需要冻结一个经过审阅的依赖版本时，使用本规则。典型对象包括 HybridCLR、Luban 以及其他带有 Editor 程序集或 `[MenuItem]` 注册的包。

本规则只约束编辑器依赖的来源、补丁和验证，不授权修改运行时协议、资源发布策略或第三方许可证条款。

## 可用方案：嵌入包优先 + 项目内最小补丁

1. 将经过审阅的包放在项目 `Packages/com.*` 下，目录名、`package.json.name` 和 `manifest.json` 依赖名必须一致。Unity 解析时，项目内有效嵌入包优先于同名 PackageCache/Git 版本。
2. 这是“项目定制版依赖”，不是自动更新机制。`manifest.json` 中保留的远程 Git 声明只能作为备用来源或升级线索；本地包存在且有效时，不得据此宣称 Unity 已经从远程拉取或自动同步。
3. 必须保留第三方许可证、版权声明、必要的 NOTICE 和上游版本信息。不得为了隐藏来源而删除许可证或伪造作者信息。
4. 所有长期补丁直接作用于项目内 `Packages/com.*` 快照，并保持最小差异；禁止把 `Library/PackageCache` 的临时修改当作长期方案。PackageCache 变更在重导入、清缓存或换机器后会丢失。
5. 对包目录执行来源/完整性门禁：目录与 `package.json` 存在、包名一致、禁止嵌套 `.git`、关键菜单补丁没有恢复，并检查 manifest 备用声明。门禁脚本是静态证据，不等同于 Unity 实机解析证据。

## 第三方菜单处理边界

- Unity 2022.3 的 `UnityEditor.Menu` 没有可用的 `RemoveMenuItem` API。不得引入不存在的 API，也不得以编译通过的兼容入口宣称菜单已隐藏。
- `[MenuItem(path, true)]` 是验证/禁用回调，只能使菜单置灰或不可执行，不能移除菜单项。需要真正隐藏时，必须在项目内嵌包源码中注释或条件编译掉原始 `[MenuItem("HybridCLR/...")]`、`[MenuItem("Luban/...")]` 等注册，并保留可审阅补丁。
- ES 自己的替代入口必须遵守 `【ES】/` 菜单根路径和现有菜单信息架构；不能通过复制第三方业务逻辑制造第二套实现。
- 空的兼容抑制器可以保留以兼容旧引用，但不得让它承担“运行时删除菜单”的虚假责任。
- 菜单扫描只说明源码中没有活动注册；仍需在 Unity Editor 中检查导入、ReloadDomain、菜单显示/禁用状态、快捷键和排序。

## 升级与回滚流程

第三方包升级必须显式进行：

1. 获取并记录新的上游版本、提交号和 release notes。
2. 对比本地快照与新版本，确认 ES 使用的 API、程序集定义、菜单路径和许可证变化。
3. 在新快照上重放最小菜单补丁及 ES 兼容补丁，禁止直接覆盖后假设补丁仍然存在。
4. 运行来源/完整性门禁、UTF-8 检查和静态编译检查；发现失败先停止升级。
5. 在目标 Unity 版本重新解析 Package Manager，确认包来源、导入和域重载；实机打开/隐藏菜单并执行一个代表性入口。
6. 保留可回滚的旧快照和补丁差异。升级完成前，成熟度统一标记为 `Implemented-Unverified` 或 `Integrating`，不得写成 Stable/Ready。

## 证据等级与禁止宣称

- “目录存在、包名匹配、菜单源码无活动注册”只能证明静态门禁通过。
- `packages-lock.json` 仍显示 `source: git` 时，只能记录为 evidence gap；没有 Unity Package Manager 运行时证据，不得宣称当前已解析为 Embedded。
- `.csproj` 或 Roslyn 静态编译通过不能替代 Unity 导入、ReloadDomain、菜单实机或运行时行为验收。
- 若静态构建被项目既有缺失源码阻断，应报告阻断文件与范围，不得把第三方包方案宣称为已失败，也不得擅自修复无关缺失。

## 维护责任

每次修改嵌入包都要同步更新上游版本记录、补丁说明、门禁脚本与本 Warning 的状态。删除本地包、恢复远程源、解除菜单补丁或改变许可证文件属于显式依赖变更，必须重新审阅并留下可复现证据。
