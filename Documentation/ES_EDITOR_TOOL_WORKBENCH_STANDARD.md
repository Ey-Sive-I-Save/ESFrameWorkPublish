# ES 编辑器工具页面规范

状态：现行规范（SimpleTools 迁移准入规则）。最后源码复核：2026-08-01。
适用源码入口：`Assets/Plugins/ES/Editor/ESMenuTreeWindow/SimpleToolsWindow`、`SimpleToolsPanelUtility.cs`、`SimpleToolsSafetyUtility.cs`、`ESEditorSection*`。
验证边界：本规范已依据当前源码完成结构与风险复核；各页面迁移后的 Unity 视觉验证、真实批处理验证和 Profiler 记录须逐页补充，不能用本文代替。

## 1. 目的与边界

SimpleTools 是 ES 的生产工具页面集合，不是“按钮集合”，也不是把 Odin 默认 Inspector 包在窗口里的集合。它服务两类同一工作流中的使用者：

- 策划先确认目标范围、规则、预览和将要产生的结果；不需要理解反射、Importer 或 Prefab 内部实现。
- 程序先确认数据源、当前状态、失败原因、可恢复性和实际执行口径；不需要从一堆彩色按钮中猜测危险程度。

任何页面只允许围绕一个明确任务组织信息：**我现在要处理什么、影响什么、下一步是什么、执行后发生了什么**。

本规范不重定义 ES 运行时架构，不允许在打开工具、刷新布局、域重载时自动扫描全项目或写入场景/资产。它只约束编辑器工具的入口、排版、状态语义和迁移验收。

## 2. 总体信息架构

左侧目录按“真实工作对象与最高风险写入类型”分类，不按“常用”或开发者个人习惯分类。一个工具只能有一个正式主入口；快捷菜单可以直达，但不得形成第二份目录树。

```text
00 工具总览与最近使用
01 观察与诊断
   运行时观察
02 场景批处理
   材质替换、Prefab 实例、对齐与布景、动画器、静态标记、重命名、灯光、粒子
03 资源与交付
   纹理与 Sprite、UnityPackage
04 ES 配置与集成
   对象池、场景与资产快捷入口
05 维护与修复
   资源引用检查、场景优化、场景文本修复
90 旧工具与待升级
```

`01 常用工具` 禁止继续存在。它会把“高频查看”与“批量改场景/资产”混为一谈，降低风险感知。

`00 工具总览` 只显示最近使用、未完成的最近结果和少量可继续任务；不能再做所有工具的等权按钮九宫格。最近记录应复用已有 `ESWindowCommandRegistry`，不为总览额外扫描资产或场景。

## 3. 当前 SimpleTools 的归属复核

| 当前工具 | 正式归属 | 页面类型 | 内部内容组织 | 最高风险行为 |
| --- | --- | --- | --- | --- |
| RuntimeWatch | 观察与诊断 | 只读诊断 | 连续观察表；低频诊断后置 | 读取属性 Getter 的副作用风险 |
| 材质替换 | 场景批处理 | 批量修改 | 场景实例 / Prefab 资产两个配置目录 | 改场景引用、改 Prefab 资产 |
| Prefab 实例管理 | 场景批处理 | 批量修改 | 范围、审计、应用/还原/替换连续流程 | 应用到资产、断开连接、替换实例 |
| 物理对齐与布景 | 场景批处理 | 批量修改 | 基础对齐、智能分布、尺寸匹配、布景整理、选区审计 | 改 Transform、布局与场景对象 |
| 动画器批量设置 | 场景批处理 | 批量修改 | 范围、Controller 策略、参数、预览、执行 | 改 Animator / Controller / 资产 |
| 批量静态设置 | 场景批处理 | 批量修改 | 规则、预览、应用 | 改 Static Flags 与烘焙相关状态 |
| 批量重命名 | 场景批处理 | 批量修改 | 规则、预览、执行、历史 | 改场景对象名称 |
| 灯光设置 | 场景批处理 | 批量修改 | 选区规则、参数、预览、应用 | 改 Light；全场景烘焙转换 |
| 粒子调整 | 场景批处理 | 批量修改 + 临时预览 | 参数、SceneView 预览、变更预览、应用 | 改 ParticleSystem / 清空粒子 |
| 纹理与 Sprite | 资源与交付 | 资产事务 | 输入、导入规则、预览、生成/应用 | 重导入、生成新资产 |
| UnityPackage | 资源与交付 | 发布事务 | 配置、资源清单、导出 | 导出/发布包、写全局配置 |
| 对象池集成 | ES 配置与集成 | 配置 + 诊断 | 运行时统计、预热审计、GameManager 接入、运行时池组 | 写 GameManager 配置、运行时加载 |
| 场景与资产快捷入口 | ES 配置与集成 | 配置 | 场景快捷、资产快捷、行为设置 | 写 `ESSceneGlobalData` |
| 资源引用检查 | 维护与修复 | 分析 + 可恢复处理 | 范围、分析、结果、隔离处理、报告 | 移动资产到隔离区 |
| 场景优化 | 维护与修复 | 高风险维护 | 概览、问题、导入设置、规则、预览、执行 | 同时改场景和项目 Importer |
| 场景文本修复 | 维护与修复 | 文件修复事务 | 目标、扫描报告、备份修复、结果 | 直接写 `.unity` 文本 |

未注册的空页面、已废弃脚本挂载工具、旧的 `Part_Build*` 兼容构建方法必须进入 `90` 的清理清单；在确认没有外部入口前不删除。

## 4. 页面骨架：固定顺序，不固定外框

所有新页面和迁移页面只可使用下列顺序。没有内容的阶段不绘制，不允许为了“统一”造空白卡片。

```text
页面标题 + 一句任务说明
当前状态行（范围 | 预览状态 | 目标数 | 风险级别）
────────────────────────────────
范围
规则 / 配置
预览 / 当前事实
主操作行
结果与复查
高级配置、调试、历史（永远后置）
```

### 4.1 标题和说明

- 标题是页面唯一的大字，使用工具名，不重复“工具”“系统”“管理器”等无意义后缀。
- 副标题必须真实绘制，最多一句，回答“这个页面解决什么”。
- 风险不是常驻大黄框。只有页面会写入或当前条件异常时，才在状态行后以一条紧凑说明出现：`会修改 32 个场景对象，可 Ctrl+Z 撤销。`
- `DrawToolHeader`、`DrawSectionTitle` 和成熟度标记传入的所有语义必须可见；当前只消费标题的实现不合格。

### 4.2 状态行

状态行只放事实，不放口号：

```text
范围：选中对象及子级（24）  ·  预览：已过期  ·  可执行：否  ·  原因：规则修改后尚未重新预览
```

状态色仅表达状态：中性、可执行、警告、错误。颜色不替代文字，也不用于装饰蓝条。

### 4.3 字段与数据表

- 一行字段完成标签、控件、短说明和状态；标签列在同页稳定，推荐 128–160px，自适应窄窗口。
- 密集结果必须使用表格：表头、稳定列宽、状态列、定位动作。行内只保留定位、勾选、复制等轻操作。
- 表格超过 30 行分页；超过 500 行必须提示范围；超过 2000 行禁止直接进入写入操作。
- 不用 `helpBox` 充当普通分区容器；普通分区靠标题、留白和细分隔线区分。`helpBox` 只属于错误、无法继续、未准备和真实警告。

### 4.4 结果与复查

执行结果固定包含：成功、跳过、失败、是否可撤销/恢复、失败项如何定位。结果默认紧凑，详情、历史和导出后置展开。

`SimpleToolsOperationReport` 是正确的基础，但不得再形成“外层盒 + 三个结果盒 + 详情盒”的嵌套盒子结构。

## 5. 操作状态机与按钮规范

### 5.1 所有可写工具的状态

```text
未准备 → 待预览 → 可执行 → 执行中 → 已完成 / 部分失败 / 已取消
```

- `未准备`：主操作禁用，并直接写明缺什么、到哪个字段修。
- `待预览`：唯一主操作为“生成预览”。
- `可执行`：唯一主操作为“应用 N 项”“导出 N 项”或“备份并修复 N 项”；必须绑定当前预览签名。
- `执行中`：禁用同一事务的重复按钮，显示进度、取消能力和已处理数。
- `部分失败`：结果区列出失败/跳过项；不把部分成功写成“执行成功”。

只读诊断页不伪造状态机：它们使用 `未刷新 / 已刷新 / 读取失败 / 已过期`，主操作为“刷新事实”。

### 5.2 按钮层级

一个页面同一时刻只允许一个视觉主按钮。

| 层级 | 用途 | 外观与位置 |
| --- | --- | --- |
| 主操作 | 生成预览、应用当前预览、导出、备份修复 | 单个、稳定位置、低饱和 ES 主色 |
| 次操作 | 刷新、定位、复制、导出报告、恢复规则 | 文字/细边按钮，跟随相关内容 |
| 风险操作 | 清空、隔离、还原、断开、移除、覆盖发布 | 后置，不与主操作等大；先显示影响，再确认 |
| 调试操作 | 反射诊断、缓存清理、强制刷新 | 只在“高级与诊断”中，不得占首屏 |

禁止继续使用 `Primary / Success / Warning / Danger` 四种大色块同时排列来承担信息层级。绿色不代表第二个主操作，黄色不代表用户已经理解风险，红色更不能替代确认。

## 6. 配置目录：全面替代 TabGroup

ES 统一使用 **ESEditorSectionNavigator（配置目录）**、`ESEditorSection`、`ESEditorBeginSection`、`ESEditorEndSection` 组织同一页面的互斥业务内容。

### 6.1 禁止项

在 SimpleTools 的新增或迁移页面中禁止：

- Odin `TabGroup`；
- `EnumToggleButtons` 作为页面/工作区导航；
- `GUILayout.Toolbar`、`EditorGUILayout.Toolbar` 作为页面导航；
- 用 `Popup` 伪装工作区切换；
- 每个分页各自独立折叠，导致用户要同时点目录和折叠两次。

枚举字段本身可保留为普通字段控件；只有它承担“切换整块业务页面”职责时才属于禁止导航。

### 6.2 使用条件

- 只有 2–8 个互斥且稳定的业务分区时使用配置目录；少于 2 个分区不创建导航。
- “范围 → 规则 → 预览 → 执行”是顺序流程，不能被拆成目录分页。
- 高级、调试、历史不是目录主项，永远在当前内容之后折叠显示。
- 相同业务分区的后续字段使用无参数 `ESEditorSection` 合并；连续字段块用 `ESEditorBeginSection` / `ESEditorEndSection` 声明，避免重复书写名称。

### 6.3 视觉与交互

```text
运行时统计  ·  预热配置审计  ·  GameManager 接入 !1  ·  池组状态
────────────────────────────────────────────────────────────
```

- 所有目录名常态可见；窄宽度自动多行绘制，不能截成 `...` 后逼用户猜。
- 选中项只使用细下划线和文字状态色；不使用凸起按钮、渐变、卡片或无语义蓝条。
- 非选中项可用低对比抽象标记表达类别；只有警告/错误/数量时才出现小状态点或 `!N`。
- 目录折叠时使用现有的长按横滑小方格交互；命中区域必须覆盖整条目录并保留上下、左右容差，不能要求精确点右侧标记。
- 内容区与目录只用一条细分隔线分开；内容区从标题到结果保持一体，不再套多层 Box。

ObjectPool、物理对齐、材质替换、场景与资产快捷入口是首批迁移对象。资源引用检查中的“目标/安全/高级”是连续配置，不应重新做成目录。

## 7. 自动扫描、性能与内存边界

1. 打开页面、重绘、切换目录、域重载不得触发全项目扫描、`AssetDatabase.FindAssets`、全场景深遍历、重导入、发布、文件写入或场景写入。
2. 扫描由用户点击“生成预览/刷新事实”显式触发；页面只渲染缓存，并标示缓存范围、生成时间和是否过期。
3. UnityPackage、Texture/Sprite 当前在绘制阶段可能构建资产预览；材质、灯光、粒子等当前在绘制阶段反复收集选区。这些属于首批性能整改项。
4. OnGUI 热路径禁止 LINQ、字符串拼接、临时 `List`、反射扫描和每帧 `FindAssets`。分页切片应复用缓存/索引而不是每次创建新列表。
5. RuntimeWatch 例外：它可在用户显式启用的观察模式下按刷新间隔采样；候选类型仍只能来自 `ESRuntimeWatchRegistry`，不得退回全对象图扫描。

## 8. 安全与恢复最低线

会写场景、Prefab、资产、Importer、文本文件或运行时配置的页面，必须在主操作可用前满足：

- 当前预览签名、目标数量和规则可见；
- 确认文案写清“会改什么、不改什么、能否撤销/恢复”；
- 场景写入：Undo、Dirty、必要时 MarkSceneDirty；
- 资产写入：路径边界、SetDirty/SaveAssets/Importer 保存；
- 清理资源：只允许隔离，不允许工具直接永久删除；
- 文件修复：先备份，再写入；
- 批量任务：成功、跳过、失败分别报告，失败项保留并支持复制/定位；
- 高风险扫描或写入不能因为用户只是打开页面而发生。

## 9. 严格分组零风险复核门禁

目录迁移和页面排版迁移必须分开提交。先做零功能风险的分组复核，再改页面实现。

每个工具都必须填写并复核以下清单，缺一项不得移动正式目录：

| 核对项 | 必须回答的问题 |
| --- | --- |
| 真实对象 | 它处理场景对象、Prefab、资产、全局配置、运行时数据还是文件？ |
| 最高影响 | 最危险的动作实际改什么？ |
| 恢复路径 | Undo、隔离、备份、回滚文件还是不可恢复？ |
| 主入口 | 左侧目录唯一正式位置是什么？快捷入口是否只做跳转？ |
| 页面类型 | 诊断、批量修改、资产事务、配置，还是修复？ |
| 目录需求 | 是否真的有 2–8 个互斥业务分区？若没有，禁止加配置目录。 |
| 主操作 | 当前状态下唯一视觉主操作是什么？ |
| 扫描触发 | 哪个明确按钮才允许扫描？缓存何时过期？ |
| 失败语义 | 不能继续时，用户在页面哪里能修？ |
| 验证证据 | 编译、Unity 手测、Undo/恢复、批量失败、性能记录分别在哪里？ |

零风险分组迁移规则：

- 只改变菜单路径和显示顺序，不改工具方法、数据格式、扫描口径或快捷命令行为。
- 保留 RuntimeWatch 的现有快捷菜单；旧路径如必须保留，只可做跳转别名，不能复制页面实例。
- 不自动保存、迁移或重写任何用户状态；目录默认展开状态仅为窗口会话显示。
- 移动前后逐项验证菜单可打开、目标页面实例唯一、快捷入口仍落到同一实例。

## 10. 迁移顺序与验收

1. **公共层**：修正 `DrawToolHeader`、`DrawSectionTitle`、结果摘要与按钮层级，使已传入的用途/副标题/风险真实可见；不改工具行为。
2. **目录层**：取消“常用工具”，按第 2 节重排。完成唯一入口与快捷跳转验证。
3. **三种样板**：RuntimeWatch（诊断）、材质替换（批量修改）、对象池（ES 配置与集成）。先由用户审看实际画面，再迁移其余页面。
4. **高风险页面**：场景优化、资源引用、场景文本修复、UnityPackage、Texture/Sprite。先收状态机和预览签名，再谈美化。
5. **其余场景工具**：按样板迁移，删除旧按钮入口和旧导航后才算完成。
6. **遗留清理**：空页面、未注册构建方法、废弃工具进入 `90` 审核；确认引用为零后再删除。

每页迁移完成的最低验收：

- 页面首屏在 600px、900px、宽窗口下均不出现横向错位、双重滚动或按钮挤压；
- 无 `TabGroup` 或旧式整页导航；
- 标题、副标题、范围、状态、主操作、失败修复位置均肉眼可见；
- 打开/重绘不会执行扫描或写入；
- 可写页通过预览、取消、成功、部分失败、Undo/恢复五条人工路径；
- 目标程序集编译通过，且性能工具页补充实际 Profiler 证据。

## 11. 实施前静态复核

```powershell
rg -n "\[TabGroup|EnumToggleButtons|GUILayout\.Toolbar|EditorGUILayout\.Toolbar" Assets/Plugins/ES/Editor/ESMenuTreeWindow/SimpleToolsWindow
rg -n "AssetDatabase\.FindAssets|FindObjectsOfType|Resources\.FindObjectsOfTypeAll|GetComponentsInChildren" Assets/Plugins/ES/Editor/ESMenuTreeWindow/SimpleToolsWindow
rg -n "DeleteAsset\(|StartAssetEditing\(|SaveAndReimport\(|DestroyImmediate\(|File\.Write|AssetDatabase\.ExportPackage" Assets/Plugins/ES/Editor/ESMenuTreeWindow/SimpleToolsWindow
```

前一条的允许项必须逐项证明“不是页面导航”。迁移完成的页面应为零命中。后两条不是禁止 API，而是强制逐项确认其触发按钮、预览、确认、恢复和失败报告。
