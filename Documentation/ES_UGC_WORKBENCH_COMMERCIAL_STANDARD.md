# ES UGC / World 工作台商业级标准

状态：现行工作台设计与验收合同。  
适用范围：`ESWorkbenchWindowBase`、`ESWorkbenchUIToolkitHost`、World 与后续 UGC 专业工作台。  
证据边界：本标准定义通过条件，不代表任一窗口已经通过 Unity 实机、Profiler 或发布验收。

## 1. 商业目标

工作台必须让作者在一个稳定会话中完成“发现内容 → 选择目标 → 视口编辑 → 检查属性 → 发现问题 → 撤销/恢复 → 保存草稿”的闭环。首屏必须回答：当前正在编辑什么、当前状态是什么、主要动作在哪里、发生失败后如何恢复。

商业级不是单纯增加颜色和按钮。底座必须同时满足可扩展性、信息架构、视觉层级、窗口自适应、交互正确性、生命周期和可验证性。

## 2. 权威对象与范围

- 工作台基础层拥有贡献注册、页面、作者模式、视口、内容库、层级、稳定选择、Inspector、命令、底部通道、布局、释放和恢复。
- 领域层拥有真实业务数据、作者操作、验证规则和正式输出后端。
- UI 与预览默认只编辑 Draft；Source、Baseline、ChangeSet、外部漂移和提交事务不得混用。
- World 必须区分 ES 作者资产、Heightfield、PreviewScene、TerrainData、正式 Scene/Prefab、导航、运行时和发布产物。
- 本轮正式 TerrainData、Scene、导航和发布事务保持关闭，不以预览或作者资产保存替代。

### 2.1 Workbench 产品语义门禁

`工作台 / Workbench` 是 ES 对完整作者会话的独占产品术语。生产窗口只有具备显式稳定 `WorkbenchId`、作者会话、稳定目标资产或文档、Draft/Commit 边界、贡献注册、统一资源/层级/视口/Inspector/命令/问题通道、Undo/Dirty、ReloadDomain 恢复和确定性释放时，才能在类型名、菜单、标题或主要产品文案中使用该术语。

`ESWorkbenchWindowBase` 是默认且唯一推荐的生产底座。特殊宿主必须登记批准的 Adapter，并完整承接同一合同。主题设置、字体工具、本地化工具、Agent 控制台、远端发布工具、对话编辑器、UI 构建工具和验证窗口不得冒用 Workbench 产品名。Popup、测试和验证类型可以保留内部技术前缀，但必须进入显式例外清单，不能登记为普通生产工作台。

静态门禁：使用 `es-editor-tooling` 的工作台语义检查与项目通用 Skill 验证器。UI ScreenSpec v3 自动装配不属于 Workbench 产品，不得通过 Workbench Skill 路由。

## 3. 可扩展贡献合同

- 贡献以 `WorkbenchId + ContributionId + TModule` 建立稳定身份。
- `TModule : struct, Enum`；每个工作台定义自己的模块枚举。
- 宿主先计算最终模块列表，再按模块列表过滤贡献。
- 注入顺序为：模块顺序 → 模块内优先级 → 依赖拓扑 → 稳定 ID。
- 一个宿主启用周期只有一个贡献会话；重载、资产重绑和关闭前确定性释放旧会话。
- 贡献移除后页面、视口、对象源、层级源、Inspector、工具、命令、问题源和旧闭包必须同时清空。
- 单贡献异常、缺失依赖、循环依赖和稳定 ID 冲突必须产生中文诊断，不能静默覆盖。

## 4. 首屏信息架构

### 顶部命令区

- 展示领域品牌、当前资产、Dirty/冲突状态、面板入口、布局入口、主命令和 ES 系统动作。
- Wide 使用单行；Compact 与 Narrow 使用双行。
- 第一行承担品牌、资产和状态；第二行承担内容、检查器、任务、布局、命令和系统动作。
- 系统、全局、窗口和页面动作保留原职责，不复制半休眠状态机。

### 左侧内容中心

- 内容库和作者层级是主要生产入口，不是辅助信息栏。
- 内容支持分类、搜索、排序、列表/缩略图、预设、批量选择和使用记录。
- Prefab、笔刷、区域模板和场景条目可在未预选时直接拖入视口。
- 拖入前只预检；拖动中显示预览和实时目标框；释放时统一经过权限、锁定、预算和 Undo 门禁。
- 拖放坐标必须以当前活动视口根节点为最终转换终点；宿主中心区坐标不得直接当作 2D/3D 渲染坐标。
- 3D 外部输入必须显式经过“工作台中心区 → 活动视口根节点 → IMGUI 渲染子节点 → 视口归一化 → 相机 Ray”的转换链；不得依赖两个当前恰好重合的 `contentRect`。
- 地形笔刷命中优先使用当前 Draft Heightfield 的射线表面，临时 TerrainCollider 只能作为普通对象选择的辅助，不得因 Collider 延迟把笔刷落点写到旧高度。

### 中央作者区

- 中央区始终获得最高面积权重。
- 2D、3D 和游戏构图是同一 Draft 的不同投影，不维护第二份业务数据。
- 工具轨、视口模式、吸附、坐标、相机、Gizmo、碰撞和导航状态具有稳定位置。
- 无资产时不创建 PreviewScene，显示“创建资产 / 打开验收样本”的商业启动面。

### 右侧 Inspector

- 只编辑当前稳定选择；目标代际变化时必须刷新。
- 使用 `SerializedObject / SerializedProperty`，并明确 Undo、mixed value、Prefab override 与多选能力。
- 目标丢失时显示原因、影响和恢复动作，禁止继续编辑旧引用。

### 底部生产通道

- 问题、历史、生产任务、日志、性能和诊断是独立通道；日志必须从持久活动存储读取，不能只复用会话状态标签。
- 收起后保留通道入口；展开高度受中央视口保护比例限制。
- 空、运行中、成功、失败、取消和部分成功具有不同中文状态与下一步。
- 主产物提供打开、定位或复制路径入口。

## 5. 响应式与高 DPI

### 尺寸分层

- `MinimumWindowWidth / Height`：理想商业最小尺寸。
- `MinimumUsableWindowWidth / Height`：高 DPI 或小屏下仍保持主路径可达的降级下限。
- 实际 `minSize` 不得超过 Unity 主窗口逻辑点工作区。
- 浮动窗口只有在越界时才调整尺寸并夹取；停靠窗口不得被业务层主动移动。

### 布局分级

- Wide：左栏、中央、Inspector 同时显示，底部可展开。
- Compact：中央优先，只显示一个侧栏；另一个侧栏可一键切换。
- Narrow：顶部双行，面板按钮显示中文短标签，侧栏互斥，所有命令保留直接入口或职责明确的溢出菜单。
- 不允许嵌套横向滚动；关键动作不依赖横向滚动才能触达。

### 比例保护

- 中央视口拥有最低绝对宽高和分级目标比例。
- 侧栏与底部抽屉同时受绝对尺寸、最大比例和可用空间三重约束。
- 用户拖动尺寸后记录为自定义布局，但不能突破中央区安全下限。
- 200% DPI 下必须至少保持中央视口、主要工具、当前选择和底部通道入口可达；底部展开高度必须让中央视口保留绝对最小高度。

## 6. 视觉与语言

- 中文是默认产品语言；技术名词可以保留英文，但必须有中文语义。
- 地形笔刷必须显式呈现模式语义（平整、抬高、降低、平滑），模式状态要同时进入 Inspector、视口提示和操作记录。
- 连续地形笔划必须由底座统一采样：首点立即落笔，移动距离超过笔刷间距时补齐中间点，释放时强制提交终点；2D 与 3D 必须共享同一采样间距和参数语义。
- 笔刷预设必须区分目标高度和平整模式、增量强度和抬高/降低模式、邻域平均和平滑模式；预设标题、Inspector、视口提示和操作记录不得互相矛盾。
- 一次连续笔划只产生一条 Undo 记录；Smooth 必须基于当前采样前的稳定快照，不能因遍历方向改变结果；取消或失去焦点必须结束捕获并清理临时状态。
- 复用 ES Presentation 的 Surface、Toolbar、状态、字体、图标和语义色。
- 品牌、状态、主操作、普通操作和危险操作必须形成清晰层级。
- 不用颜色单独表达状态；必须同时提供文字、图标或结构语义。
- 长中文、路径、GUID、Hash、异常和日志支持换行、截断提示与完整复制。
- 装饰不能牺牲事件隔离、目标正确性、单一滚动容器和重绘性能。

## 7. 状态、失败与恢复

- 无资产：说明当前状态，提供创建和样本入口。
- 加载中：显示目标与阶段，避免空白视口。
- 验证失败：显示原因、影响范围和就近修复动作。
- 外部漂移：锁定提交，保留 Draft，提供重载或人工合并入口。
- 提交后同步失败：明确作者数据是否已经提交，不能谎报整体回滚。
- Domain Reload 后只恢复稳定身份、布局、Draft 文本、Hash、ChangeSet 和必要版本。

## 8. 生命周期与性能

- 页面只在离开当前页、贡献重载、资产重绑或窗口关闭时释放。
- PreviewScene、Camera、RT、临时对象、回调、PropertyTree 和 `SerializedObject` 必须确定性释放。
- 不在 AssemblyStream、ReloadDomain 或窗口打开时执行全项目资产扫描。
- 不在重绘热路径创建纹理、Skin、Preview、反射目录或大临时集合。
- 主题切换、窗口重建和重复打开不得产生重复宿主、重复订阅或旧闭包。

## 9. 商业验收矩阵

每次候选版本至少覆盖：

- Wide / Compact / Narrow；
- 100% / 125% / 150% / 200% DPI；
- 深色 / 浅色；
- 普通中文 / 长中文压力；
- 无资产 / 有资产 / Dirty / 外部冲突 / 失败恢复；
- 内容搜索、分类、拖放、实时目标框、预览、移动、锁定、Undo/Redo；
- 地形笔划首点、间隔补点、释放终点、边界裁剪、平整/抬高/降低/平滑四种语义和一次 Undo；
- 2D / 3D / 游戏构图切换与状态保持；
- 3D 视口鼠标落点必须实时投影为世界坐标并进入底部状态栏；移出视口后清除，不能残留旧坐标；
- 贡献删除、新增、排序、模块去重、依赖、重复加载和旧页面释放；
- 资产重绑、窗口关闭重开和 ReloadDomain；
- Console、EditMode 测试、真实窗口截图与交互记录；
- Profiler / Memory 资源释放和重绘分配检查。

## 10. 完成声明

- S1：源码存在；
- S2：目标静态工程构建通过；
- S3：Unity 导入、Console 和 ReloadDomain 通过；
- S4：真实窗口交互与截图矩阵通过；
- S5：需要运行态的能力通过 PlayMode 或运行观察；
- S6：Player、IL2CPP、资源与发布链路通过。

工作台只有达到任务明确要求的证据层级才可称为 `Accepted`。单张截图、测试源码或 `.csproj` 构建不能单独证明商业级完成。
