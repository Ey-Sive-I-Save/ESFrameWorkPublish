# Contributing to CC0Tree

Thanks for wanting to contribute! CC0Tree is primarily a solo project, but contributions are welcome in a couple of forms.

## Contributing an asset

If you'd like to add your own asset to the library:

- **It must be your own original work, and you must be willing to release it under CC0** (public domain — no attribution required, no restrictions, no ownership retained). By opening a PR that adds an asset, you're confirming you have the right to do this and agreeing to the CC0 dedication. Assets that aren't clearly your own original work, or that come with any licensing strings attached, won't be merged.
- **Format**: FBX, placed in `Assets/`, named `SM_YourAssetName.fbx` to match the existing convention.
- **Style**: low-poly and game-ready. It doesn't need to match the gradient-shaded look of the rest of the library, but it should be lightweight and consistent with the spirit of the project — fast to load, easy to use, not a photoreal asset.
- **Optional but appreciated**: a render/icon in `Icons/`, named to match the asset filename — see the existing files for the naming pattern. If you skip this, the site will just show a fallback icon until one's added.

## Reporting a problem or suggesting an asset

Don't want to submit a PR? Open an [issue](../../issues/new/choose) instead — there are templates for reporting a bug and for suggesting an asset idea. Suggestions aren't guarantees anything gets made, but they're genuinely read.

## Website / tooling changes

Bug fixes or improvements to `index.html` or the repo's tooling are welcome via PR too. Keep changes focused and explain the reasoning in the PR description.
