### T01：建立密集信息编辑器的通用排版方向

- **用户任务**：为高字段量页面定义商业级、可读、低负担的通用排版方案，并明确高级配置、诊断和风险操作的顺序。
- **接受范围**：统一用户看到的信息顺序与状态语义，不把 Inspector 改造成全项目窗口框架。
- **实际动作**：形成标题、细分隔线、稳定列宽、折叠层级、单一主操作、错误解释和显式触发的约束。
- **结论**：复杂集合转表格或专门编辑器；自动扫描、写资产、发布和场景修改不得绑定打开/刷新/域重载。

### T02：命名并定位编辑器内容目录

- **用户任务**：设计替代传统 TabGroup 的目录式内容分区，并确认 Inspector 与窗口嵌入的命名边界。
- **实际动作**：确定 `ESEditorSectionNavigator`、`ESEditorSection`、`ESEditorSectionStatus`，将其定位为编辑器内容目录而非传统页签控件。
- **结论**：同一绘制方案可嵌入 Inspector、Odin 窗口或其他宿主；目录负责导航，Odin 继续绘制原始属性。

### T03：实现 Section 原型并处理首帧与 Odin 分组错误

- **用户任务**：开始实装、补写案例，解决目录首帧不可见和 `ESEditorSectionAttribute` 缺失父组报错。
- **实际动作**：依据历史交付复核 `PropertyTree → SectionIndex → 原始属性绘制` 链路；将分组建立责任收口到 Processor/合法父组。
- **证据与结论**：`__ESEditorSection` 父组缺失、`HorizontalGroup`/`VerticalGroup` 父组缺失均被记录为回归项；不合法分组必须可诊断回退。

### T04：反复校正 Section 的视觉和交互

- **用户任务**：解决蓝条无语义、边界不清、英文代号难懂、选中效果弱、按钮过小、长按滑动难用、分页折叠痛苦等问题。
- **实际动作**：收敛为业务目录条；支持常态显示名称、可选副标题、共享折叠、两端宽松命中和按住横向滑动；内容区与目录区分出轻边界。
- **结论**：不再使用厚重 Tab/Button 堆叠；颜色、下划线和层级只表达当前选中与状态，不承担装饰性主视觉。

### T05：推进多态引用编辑体验

- **用户任务**：替代 Odin 原生多态序列化的丑陋界面，支持类型目录、搜索、嵌套、清除、Undo、重选和多目标编辑。
- **实际动作**：推进 `ESPolymorphicReferenceDrawer`、`ESTypeCatalog`、`PropertyTree` 链路及演示脚本；约束多目标上限为 10 个并保留集合/深层嵌套边界。
- **结论**：类型目录负责收集和筛选，不把多态语义硬编码进通用下拉；空值、缺失类型、深度和循环风险需显示原因与修复入口。

### T06：处理 AdvancedDropdown 反射注入失败

- **用户任务**：把多态工具按钮接入 Unity 原生 AdvancedDropdown 同一视图。
- **实际动作**：复核内部 `AdvancedDropdownGUI` 构造函数及搜索字段调用的反射路径。
- **证据与结论**：出现 `MethodAccessException`；内部构造函数/方法不是稳定公共 API，因此保留原生 AdvancedDropdown 回退，不再把反射注入宣称为已完成能力。

### T07：为案例物体补充职责说明

- **用户任务**：常见测试对象自带 ReadMe，说明每个对象的清晰职责。
- **实际动作**：将 `ESReadMeNote` 接入 RuntimeWatch、ItemMotion、资源流程和多态边界案例，并补充一键创建、选择、定位测试层级的入口。
- **结论**：案例说明属于上手路径的一部分，不与业务组件职责混写。

### T08：重排 SimpleTools 公共工作台

- **用户任务**：大部分简单工具排版错乱，要求整理为正常工具页面，统一范围、规则、预览、主操作、结果和风险。
- **实际动作**：依据历史交付复核 `DrawToolHeader`、目录、按钮层级和状态语义；移除泛滥外框、彩色主按钮和无意义分组。
- **结论**：页面只保留一个视觉主操作；重建、清理、迁移等风险操作后置并带确认和结果反馈。

### T09：修复 Layout/Repaint 与 Odin Group 崩溃

- **用户任务**：处理 ObjectPool 的 `Getting control ... position`，以及 PhysicsAlign 的 `HorizontalGroup`/`VerticalGroup` 缺失父组错误。
- **实际动作**：将采样和渲染快照分离，避免 Layout/Repaint 改变控件数量；将成员引用的父组建立责任前置并保持合法层级。
- **证据与结论**：错误被保留为失败记录和回归验收项；连续重绘的对象/List 复用和 Profiler GC 仍未完成实测签收。

### T10：收紧 RuntimeWatch 采集门禁

- **用户任务**：RuntimeWatch 不应在窗口未打开时损耗；打开后才允许大量采集，平时仅初始化一次。
- **实际动作**：复核 `EditorApplication.update` 注册、菜单选中、窗口焦点、有效尺寸与销毁注销逻辑。
- **结论**：隐藏页面和后台 Dock 标签暂停自动采集；重新聚焦后恢复。像素级可见性和 Unity Dock 实测仍不能由静态代码代替。

### T11：明确刷新、录制与慢 Getter 语义

- **用户任务**：刷新不应要求重新获得焦点后才能工作；解释慢 Getter 与读取失败状态；准备 RuntimeWatch 发布视频流程。
- **实际动作**：把“立即刷新”定义为一次性显式动作，录制定义为持续采样租期；将慢 Getter 定义为读取耗时超阈值，读取失败定义为异常/不可访问值并显示原因。
- **结论**：窗口关闭时无采集；窗口打开但未处于前台时暂停；诊断信息必须告诉用户影响和下一步。

### T12：收口 GameCore 属性配置与代码生成边界

- **用户任务**：确认普通属性配置是否需要生成代码，以及固定访问名的必要范围。
- **实际动作**：复核属性表字段顺序、Bake 与固定 API 触发条件，明确稳定键走 `EnumKey/StringKey → Bake Catalog → RuntimeKey`。
- **结论**：普通配置不触发编译；只为已证明的高频、固定槽位路径生成具名 API。

### T13：补齐资源生命周期与 Raw 规则

- **用户任务**：找出 AIWarnings 未覆盖的重要资源规则并写入现行约束。
- **实际动作**：收口 Resident/Owner/Temporary、`LoadAsyncLease`、ReferenceCount/LeaseCount、generation、安全点、Provider 切换、Raw TextAsset、ContentBinding 和 ResourcePlan Extension 语义。
- **结论**：Provider 不得自行创建 Scope 或重复加载；Lease 必须与 Plan 绑定并在取消、异常、Dispose 时逆序释放；Publish Extension 当前仍未实现。

### T14：补齐 GameManager 与 ESGameSave 语义

- **用户任务**：避免 AI 继续传播隐式创建模块的旧 API。
- **实际动作**：将 `TryGetModule<T>()` 定义为只查询，将 `GetOrCreateModule<T>()` 限定为初始化期显式创建；补充 `ESGameSave` 的 Get/Has/Save/Delete/Info 与 Set/Load 创建边界。
- **结论**：旧 `GetModuleFast<T>()` 只能作为禁止/迁移背景，不得作为推荐高频 API。

### T15：补齐 SoDataInfo / Group / Pack 边界

- **用户任务**：确认 Info、Group、Pack 是否可以互相替代或作为默认聚合。
- **实际动作**：写入 P0 规则：具体 `SoDataInfo` 必须有对应 `SoDataGroup<TInfo>`，正式 Info 必须有唯一主 Group，`SoDataPack<TInfo>` 默认冻结。
- **结论**：Group 只负责编辑器组织和启动聚合，不替代 ResourcePlan、Scope、Manifest 或发布包。
