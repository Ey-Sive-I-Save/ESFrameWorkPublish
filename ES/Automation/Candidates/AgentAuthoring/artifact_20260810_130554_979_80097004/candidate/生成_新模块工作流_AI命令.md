# 生成新模块工作流

命令类型：安全执行
默认改文件：是，仅限声明范围；只允许修改用户目标和 Graph Constraint 明确列出的项目文件。
风险等级：L2

## 任务目标

把用户给出的中文目标整理为一条能够真实执行、可复核、可验证的 ESFramework 实现链，并在当前授权范围内完成实际修改。不得以方案、伪代码、推测性结论或未经执行的验证冒充完成。

## 预期输入

- 用户目标。
- 当前实现事实与已知问题。
- 必读规则和领域专项资料。
- 允许修改的明确项目路径。
- 验收标准以及需要取得的证据等级。

如果目标范围、允许修改路径或验收标准不足以确定安全实现边界，必须先停止相关写入并报告所缺决策。

## 必须先读

1. `Assets/Plugins/ES/AIWarnings/00_开始阅读（Start）/README.md`
2. `Assets/Plugins/ES/AIWarnings/00_开始阅读（Start）/当前状态（CurrentStatus）.md`
3. `Assets/Plugins/ES/AIWarnings/00_开始阅读（Start）/规则索引（RuleIndex）.md`
4. 规则索引按当前任务命中的 P0 原文和领域专项原文。
5. 当前任务相关的源码、配置、测试和现有文档；旧摘要不得替代当前源码事实。
6. 当前会话中命中的项目 Skill 的完整 `SKILL.md`。Skill 只提供工作流，不扩大用户授权。

涉及中文或其他项目文本修改时，必须额外读取：

- `Assets/Plugins/ES/AIWarnings/10_P0最高约束（P0Guardrails）/编码与文本（Encoding）/项目最高警告_P0_UTF8唯一编码_禁止AI默认代码页覆写与机械转码_AI协作警告.md`
- `.agents/skills/es-utf8-guard/SKILL.md`

## 执行边界

### 前置条件

- 目标范围、权威规则和允许修改路径已经明确。
- 已只读核对当前分支、HEAD、工作树和目标路径差异。
- 已区分用户或其他 AI 的既有改动、本任务改动以及可能重叠的改动。

### 允许操作

- 读取完成任务所必需的项目规则、源码、配置和测试。
- 只修改用户目标和当前任务约束明确允许的项目文件。
- 运行与改动风险相称的静态检查、目标工程编译和适用测试。
- 为交付提供真实差异、命令输出、失败信息和未执行验证清单。

### 禁止操作

- 不得扩大用户授权或擅自修改无关文件、并行分支和现有用户改动。
- 不得擅自删除文件、执行 Git staging、commit、reset、clean、push、发布或上传。
- 不得手改 Unity 生成的 `.csproj` 文件来制造编译通过。
- 不得把生成工程编译冒充 Unity Editor、ReloadDomain、Test Runner、PlayMode、Profiler、Player 或 IL2CPP 验证。
- 不得伪造测试、编译、Unity Console、运行行为或人工批准结果。
- 不得使用 PowerShell 默认代码页覆写中文或编码未知的项目文本，也不得机械转码整个文件或目录。

### 阻断与回滚

- 遇到越权、必需依赖缺失、规则冲突或目标路径并行重叠时，停止相关写入，报告阻断位置和所需决策。
- 本轮写入失败时，只回滚本事务新产生且能明确归属的改动；不得撤销用户或其他 AI 的并行修改。
- 无法安全区分本轮与既有改动时，不执行破坏性回滚，保留现场并报告。

## 实现步骤

1. 根据用户目标从规则索引选择最小且完整的权威规则集，逐份读取命中的 P0 和领域专项原文。
2. 核对当前分支、HEAD 与工作树；分别检查目标路径的 unstaged、staged 和 untracked 状态，确认没有会被覆盖的并行工作。
3. 回读目标源码、调用链、数据入口、测试和现有文档，形成“当前已实现事实、缺口、允许修改点、证据入口”的简短实现基线。
4. 把中文需求拆成按依赖排序的实现链。每一步必须明确输入、目标文件、职责边界、失败条件和可验证结果。
5. 使用最小范围修改完成真实实现。优先复用项目现有协议、注册入口、生命周期和测试设施，避免建立第二套相同职责系统。
6. 修改后检查目标差异，确认没有整文件异常改写、任务外变化、乱码、默认代码页污染或换行漂移。
7. 运行相关静态检查、目标工程编译和适用测试。需要 Unity、PlayMode、Profiler、Player、IL2CPP、网络或人工交互而当前不可用的验证，必须明确记录为“未执行”。
8. 再次审计工作树，确认交付列出的文件与实际差异一致，并保留所有无关既有改动。
9. 按下述交付结构报告真实证据。若验收未全部满足，不得声称任务完整通过。

## 验证结果

交付时必须分层列出：

- 静态检查：实际执行的命令、退出码和关键结果。
- 源码或目标工程编译：工程名、命令、警告数和错误数。
- 自动化测试：测试范围、通过/失败/跳过数量及失败入口。
- Unity 验证：Editor 编译、ReloadDomain、Console、EditMode、PlayMode、Profiler、Player、IL2CPP 分别说明已执行或未执行。
- 外部验证：网络、发布、上传、真实设备或人工交互分别说明是否获得授权并实际执行。

已有历史结果只能作为上下文，不得冒充本轮结果。命令未运行、工具不可用或被无关错误阻断时，必须如实记录。

## 改动文件

交付时逐项列出本轮实际修改、创建或删除的文件，并为每个文件说明：

- 修改目的。
- 关键行为变化。
- 是否存在本轮开始前的重叠改动。
- 对应的验证证据。

如果没有实际修改授权或写入因阻断未发生，必须明确说明任务未达到本命令的完成定义，不能只输出建议后声称完成。

## 剩余风险

至少列出：

- 尚未执行的验证及其原因。
- 仍依赖 Unity、运行环境、外部服务或人工操作确认的内容。
- 已知但不在本次授权范围内的问题。
- 并行工作树、序列化资产、迁移、兼容性、性能或发布方面的剩余风险。
- 下一步需要的最小授权或决策。

## 完成定义

只有同时满足以下条件才可报告完成：

1. 已按实现链真实修改授权范围内的目标文件，而非只给方案。
2. 已列出实际源码差异和全部改动文件。
3. 已运行当前环境可用且适用的编译与测试，并报告真实结果。
4. 已把未执行的 Unity 或发布验证与已执行证据严格分层。
5. 已保留用户和其他 AI 的无关并行修改。
6. 已列出未完成项、剩余风险和需要的后续决策。
