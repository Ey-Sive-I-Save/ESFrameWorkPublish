## 当前已确认事实

### 角色与控制

- `EntityCharacterProfile` 是角色 Prefab 身份和 DataInfo 的唯一入口：`CharacterVariant` 自动绑定唯一 DataInfo；`RuntimePoolTemplate` 由租出方调用 `Entity.BindDefinition(...)`；`BuildInput` 不绑定定义。
- `Entity` 是身体、KCC、Domain 和挂点服务入口；基础能力通过 Basic Domain Module，当前动作/环境由 StateMachine 管理。
- 正式“大黑塔” Variant 当前实际装配的主要玩法模块是移动、输入调度、骑乘、攀爬和玩家输入写入。它是角色控制测试 Variant，不是完整商业动作 RPG 玩家角色。
- 当前枪械基础模块只完成射线、状态、后坐力与命中点记录；统一伤害、生命、受击、死亡、阵营和部位结算尚未闭环。
- 武器挂点与双手 IK 仍有制作风险：WeaponSocket 映射与副手目标语义需在正式内容生产前复核；基础模板的 Solver 默认关闭。

### Layer 与物理

- `TagManager`、`GameCoreEditorGlobalData.physicsLayers` 与 `DynamicsManager` 的 15 条 ES 管理 Layer 已静态逐对核对，碰撞矩阵不一致数为 `0`。
- 核心分层：EntityBody 6、Ground 8、Wall 9、WorldDynamic 10、EntityHurtbox 11、ItemBody 12、Interaction 13、TriggerZone 14、Shot 15、CameraBlocker 16、Sensor 17。
- 正式角色与三台方块载具、玩家控制器测试场景的关键 Collider 静态落层正确；这是静态资产结论，不替代 PlayMode。
- 仍有 P1：部分通用攀爬、交互、脚部 IK、基础战斗代码采用 `~0` 或 `Physics.DefaultRaycastLayers` 默认查询。新正式模板必须改用 `ESPhysicsLayers` 语义 Mask，不能靠制作人员记忆。

### 载具、相机与技能

- 载具根由 `VehicleController` 独占运动写入；座位由 `EntityMountable` 管理，骑手输入经座位提交给 Controller。角色不挂 VehicleController。
- 载具源码已具备驾驶权、输入过期、Controller 禁用撤销骑手、Rigidbody/KCC 后端及能力调度隔离的设计；仍需 Unity PlayMode 验收。
- Camera 的 Director / Lease / ViewId / SceneBinding / CM2 Adapter / Skill Camera Track 源码存在，但 CurrentStatus 规定其仅为待 Unity 收录与运行验收的 P0 骨架，禁止称稳定可用。
- Skill 轨道有动画、音频、对象、操作和 Camera 源码；正式 Combat Hit/Damage 轨、Timeline 运行验收、TrackView 预览验收仍未签收。

## 已冻结的行为扩展方向

```text
BehaviorProfile：声明稳定行为 Key 与参数
Domain Module：生命周期、调度、缓存与最终写入权
Policy / Strategy：单一可替换算法，只计算
StateMachine：当前互斥动作与表现环境
Coordinator / Transaction：跨领域流程和原子提交
```

行为配置不得保存 `System.Type`、程序集名、委托、RuntimeKey 或场景实例；运行时只在创建、绑定或对象池租出时解析并缓存。不要把这项设计讨论误写成已经实现的 `StrategyCatalog`。
