ESFrameWork 快速开始

ESFrameWorkPublish 是一个面向 Unity 的模块化游戏框架。它以 ESGameManager 为全局 Core，按系统、流程、世界三个 Domain 收纳模块，并为常用运行时能力建立默认模块。

从 ESGameManager 启动

在启动场景创建一个 ESGameManager 组件。它以较早的 Unity 执行顺序运行，建立单例并可选择跨场景保留；随后注册三个 Domain，再按 Inspector 开关取得默认模块。

创建全局管理器

在首个场景放置一个空对象并添加 ESGameManager。重复实例会在 Awake 中被销毁。

决定持久化策略

默认 dontDestroyOnLoad = true，场景切换后管理器继续保留。

检查默认模块开关

命令、输入、运行时数据、对象池、物理查询与 LOD 模块都由管理器的布尔配置控制。

// 场景中只需要一个 ESGameManager
using ES;

public sealed class GameBootstrap : MonoBehaviour
{
    [SerializeField] private ESGameManager gameManager;

    private void Awake()
    {
        // ESGameManager 自身会在 Awake 中注册 Domain 与默认模块。
        Debug.Assert(gameManager != null);
    }
}
启动时序

OnBeforeAwakeRegister 会发送全局唤醒事件；OnAwakeRegisterOnly 注册 Domain；OnAfterAwakeRegister 再按开关创建默认模块。

Core / Domain / Module

框架把全局能力按职责分层。Core 持有全局生命周期，Domain 限定模块类别，Module 则承载具体运行能力。这个边界由泛型基类表达，而不是只依赖目录命名。

ESGameManager 的模块边界

ESGameManager : Core全局单例与生命周期入口
ESSystemDomainESSystemModule
ESFlowDomainESFlowModule / ESRuntimeModule
ESWorldDomainESWorldModule / ESPlayerModule

ESSystemModule、ESFlowModule 与 ESWorldModule 都提供 Game 访问器以及 TryGetModule、GetOrCreateModule 辅助方法。运行时模块继承自流程模块，玩家模块继承自世界模块。

运行时数据与资源桥接

ESRuntimeDataGameCore 为 Buff、Shot、Monster、NPC、Weapon 和 Skill 各保留一张运行时 Key 表。ESRuntimeDataAsset 则建立 Prefab、Sprite、音频、动画、场景等资产类型表，并在全量重建前检查构建状态与未完成加载。

数据层代表表职责
GameCoreESBuffConfigKeyTable为战斗和游戏配置建立运行时查找表。
AssetESAssetConfigKeyTable<T>按资源类型登记并协调异步加载状态。
BootstrapESRuntimeDataBootstrapBridge在场景加载前登记初始化回调，也支持动态程序集加载后的显式登记。

发布资源启动桥会在资源初始化时确保管理器和运行时数据模块存在；如果二者均未建立，它会创建名为 ESGameManager 的对象，然后异步初始化资源加载。

状态系统

StateBase 是状态本体的 partial 类型入口，具体职责拆分为 Core、Pooling、Animation、Progress、IK、MatchTarget 和 Debug 文件。状态机负责驱动进入、更新和退出；业务侧要与状态严格同步时，应复用 StateLifecycleTracker，而非重复实现布尔生命周期守卫。

绑定与运行时缓存

BindHostMachine 绑定宿主状态机后刷新共享数据缓存。实现明确将配置引用与特性标记缓存到字段，使每帧 Update 热路径读取缓存；缺少动画配置或 Calculator 时会降级为无动画，避免空引用。

标签集合

ESTagCollection 是与 Entity 和业务权限解耦的通用运行时标签容器。它维护引用计数、热标签位掩码、稀疏标签、快照与变更事件。外部系统可通过 Acquire 获得 ESTagLease；宿主自身则可用 SetTag 管理自己的单一贡献。

所有权约定

源码明确区分宿主的无句柄写入与外部系统的 Lease/LeaseSet 写入。这样关闭宿主标签时，只会移除宿主自己的增量，不会影响其他贡献者。

物理查询

物理模块集中定义项目 Layer 与组合查询掩码，并以 RaycastNonAlloc、SphereCastNonAlloc 和 Overlap NonAlloc API 执行查询。它维护共享 Raycast/Collider 缓冲区、计数器和容量溢出记录。

  • 通过 ESPhysicsLayers 集中复用移动、地面探测、飞行物命中、交互和 AI 掩码。
  • 启动时创建指定容量的共享缓冲区；配置变更后按需重新分配。
  • 当返回数量达到缓存容量时，记录 overflowCount，用于发现缓冲区不足。
